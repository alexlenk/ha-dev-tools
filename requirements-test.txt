# Home Assistant core (required for integration testing).
# Pinned via pytest-homeassistant-custom-component's own exact pin (below)
# rather than a floor on `homeassistant` directly, because HA's own
# Requires-Python has climbed release over release (>=3.12.0 through
# 2025.1.x, >=3.13.0 for 2025.2-2025.4, >=3.13.2 for 2025.5-2026.2,
# >=3.14.2 from 2026.3 on - checked directly against PyPI, not assumed).
# An earlier version of this comment claimed mcp_server (which serves the
# dev_tools llm.API over MCP, added in homeassistant/core's dev branch)
# "hadn't reached a stable release yet" - that was wrong. It shipped in
# 2026.3+; homeassistant==2026.8.2 has it. What was actually happening:
# CI's Python 3.12/3.13 matrix couldn't install anything past 2025.1.4 (the
# last release still supporting <3.14), so a bare `homeassistant>=2024.1.0`
# floor silently resolved to the newest Python-3.12-compatible release
# instead of erroring - it looked like "not on PyPI" but was really "not
# installable on this interpreter". Fixed by moving the CI matrix to Python
# 3.14 (see test.yml) and pinning here to a pytest-homeassistant-custom-
# component release whose own exact homeassistant pin includes mcp_server.
pytest-homeassistant-custom-component==0.13.356
